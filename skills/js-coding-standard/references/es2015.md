> 适用：项目构建目标达到 ES2015 时作为语言基线使用，是本 skill 正文章节的基线。目标版本更高时，须同时适用 `es2016-2019.md`、`es2020-2022.md` 中对应章节；跨版本的质量规范（相等比较、命名、注释、安全等）见 `general-quality.md`；ES5 遗留环境见 `es-legacy.md`。

## 一、块级作用域与变量声明

### 1. let 取代 var

ES2015 提供了 `let` 和 `const` 两个新的变量声明命令。`let` 完全可以取代 `var`：两者语义相同，且 `let` 没有副作用。

### 2. 优先使用 const，全局环境只设常量

在 `let` 和 `const` 之间建议优先使用 `const`，尤其全局环境不应设置变量、只应设置常量。

`const` 声明常量有两个好处：一是阅读代码的人立刻意识到该值不应修改，二是防止无意间修改变量值导致的错误。

```js
// ❌
var a = 1, b = 2, c = 3;

// ✅
const a = 1;
const b = 2;
const c = 3;

// ✅ 最佳
const [a, b, c] = [1, 2, 3];
```

### 3. 声明细节

- 一条语句只声明一个变量（Airbnb 13.2）
- 同一作用域内 `const` 声明在前、`let` 在后（Airbnb 13.3）
- 禁止链式赋值（`let a = b = c = 1` 会产生隐式全局变量）（Airbnb 13.5）
- 不使用 `++` / `--`，使用 `+= 1` / `-= 1`（Airbnb 13.6；与 for 循环惯用写法冲突时，按项目约定）

```js
// ❌
let a = b = c = 1;
num++;

// ✅
let a = 1;
let b = 1;
let c = 1;
num += 1;
```

## 二、字符串

- 静态字符串一律使用单引号，不使用双引号
- 反引号（模板字符串）仅用于含插值或换行的动态字符串（Airbnb 6.1/6.3），不使用字符串拼接

```js
// ❌
const a = "foobar";
const b = 'foo' + a + 'bar';

// ❌ 静态字符串无需用反引号
const c = `foobar`;

// ✅
const a = 'foobar';
const b = `foo${a}bar`;
```

## 三、解构赋值

### 1. 数组成员赋值优先使用解构

```js
const arr = [1, 2, 3, 4];

// ❌
const first = arr[0];
const second = arr[1];

// ✅
const [first, second] = arr;
```

### 2. 函数参数是对象的成员时，优先使用解构

```js
// ❌
function getFullName(user) {
  const firstName = user.firstName;
  const lastName = user.lastName;
}

// ✅
function getFullName(obj) {
  const { firstName, lastName } = obj;
}

// ✅ 最佳
function getFullName({ firstName, lastName }) {
}
```

### 3. 多返回值优先用对象解构，而非数组解构

便于以后添加返回值、更改返回值顺序：

```js
// ❌
function processInput(input) {
  return [left, right, top, bottom];
}

// ✅
function processInput(input) {
  return { left, right, top, bottom };
}

const { left, right } = processInput(input);
```

## 四、对象

### 1. 逗号规则

- 单行定义的对象：最后一个成员**不以**逗号结尾
- 多行定义的对象：最后一个成员**以**逗号结尾

```js
// ❌
const a = { k1: v1, k2: v2, };
const b = {
  k1: v1,
  k2: v2
};

// ✅
const a = { k1: v1, k2: v2 };
const b = {
  k1: v1,
  k2: v2,
};
```

### 2. 使用字面量创建对象与简写形式

- 使用字面量 `{}` 创建对象，不使用 `new Object()`（Airbnb 3.1）
- 对象方法使用简写、属性名与变量同名时使用属性值简写（Airbnb 3.3/3.4）
- 仅当属性名不是有效标识符时才加引号（Airbnb 3.6）

```js
// ❌
const atom = {
  value: 1,
  addValue: function (value) { return atom.value + value; },
};

// ✅
const value = 1;
const atom = {
  value,
  addValue(value) { return atom.value + value; },
};
```

### 3. 对象尽量静态化，扩展用展开运算符

对象一旦定义，不得随意添加新属性；确需扩展时优先使用展开运算符浅拷贝生成新对象（Airbnb 3.8，ES2018+，示例见 `es2016-2019.md`；ES2015 环境用 `Object.assign({}, a, { x: 3 })` 且不得修改原对象）：

```js
// ❌
const a = {};
a.x = 3;

// ✅ 定义时声明
const a = { x: null };
a.x = 3;
```

### 4. 动态属性名用属性表达式

属性名是动态的，应在创建对象时使用属性表达式定义：

```js
// ❌
const obj = {
  id: 5,
  name: 'San Francisco',
};
obj[getKey('enabled')] = true;

// ✅
const obj = {
  id: 5,
  name: 'San Francisco',
  [getKey('enabled')]: true,
};
```

### 5. 不直接调用 Object.prototype 方法

`hasOwnProperty` 等方法可能被对象自身属性遮蔽，用 `Object.prototype.hasOwnProperty.call` 调用（Airbnb 3.7）；ES2022+ 环境改用 `Object.hasOwn`（见 `es2020-2022.md`）：

```js
// ❌
object.hasOwnProperty(key);

// ✅
Object.prototype.hasOwnProperty.call(object, key);
```

## 五、数组

### 1. 使用扩展运算符（...）拷贝数组

```js
const items = [1, 7, 3, 4, 0];

// ❌
const itemsCopy = [];
for (let i = 0; i < items.length; i++) {
  itemsCopy[i] = items[i];
}

// ✅
const itemsCopy = [...items];
```

### 2. 转换数组：可迭代对象用展开，类数组对象用 Array.from

```js
const foo = document.querySelectorAll('.foo');

// ✅ 类数组对象用 Array.from
const nodes = Array.from(foo);

// ✅ 最佳：可迭代对象直接展开
const nodes = [...foo];

// 带映射转换时用 Array.from，避免中间数组
const bars = Array.from(foo, bar);
```

### 3. 创建与追加

- 使用字面量 `[]` 创建数组，不使用 `new Array()`（Airbnb 4.1）
- 追加元素使用 `push`，不使用长度索引赋值（Airbnb 4.2）

```js
// ❌
const someStack = [];
someStack[someStack.length] = 'abracadabra';

// ✅
const someStack = [];
someStack.push('abracadabra');
```

## 六、函数

### 1. 立即执行函数写成箭头函数形式

```js
(() => {
  console.log('Welcome to the Internet.');
})();
```

### 2. 匿名函数作参数时用箭头函数代替

更简洁，且绑定了 `this`：

```js
// ❌
[1, 2, 3].map(function (x) {
  return x * x;
});

// ✅
[1, 2, 3].map((x) => {
  return x * x;
});

// ✅ 最佳
[1, 2, 3].map(x => x * x);
```

### 3. 箭头函数取代 Function.prototype.bind

不应再用 `self` / `_this` / `that` 绑定 `this`：

```js
// ❌
const self = this;
const boundMethod = function (...params) {
  return method.apply(self, params);
}

// 可接受
const boundMethod = method.bind(this);

// ✅ 最佳
const boundMethod = (...params) => method.apply(this, params);
```

### 4. 箭头函数与传统函数的取舍

- 简单的、单行的、不会复用的函数：建议采用箭头函数
- 函数体较为复杂、行数较多：还是应采用传统的函数写法

### 5. 配置项集中在一个对象，放在最后一个参数

布尔值不可以直接作为参数（clean-code：flag 参数使函数同时承担两种职责）：

```js
// ❌
function divide(a, b, option = false) {
}

// ✅
function divide(a, b, { option = false } = {}) {
}
```

### 6. 用 rest 运算符（...）取代 arguments

rest 运算符显式表明想要获取的参数，且提供一个真正的数组；`arguments` 只是类数组对象：

```js
// ❌
function concatenateAll() {
  const args = Array.prototype.slice.call(arguments);
  return args.join('');
}

// ✅
function concatenateAll(...args) {
  return args.join('');
}
```

### 7. 使用默认值语法设置参数默认值

```js
// ❌
function handleThings(opts) {
  opts = opts || {};
  // ...
}

// ✅
function handleThings(opts = {}) {
  // ...
}
```

> 参数卫生（不修改/重赋值参数、默认参数放最后）见 `general-quality.md`"函数参数卫生"。

## 七、Map

### 1. 区分 Object 与 Map

只有模拟现实世界的实体对象时才使用 Object；如果只是需要 `key: value` 的数据结构，使用 Map 结构——Map 有内建的遍历机制。

## 八、Class

### 1. 总是用 Class 取代需要 prototype 的操作

Class 的写法更简洁、更易于理解：

```js
// ❌
function Queue(contents = []) {
  this._queue = [...contents];
}
Queue.prototype.pop = function () {
  const value = this._queue[0];
  this._queue.splice(0, 1);
  return value;
}

// ✅
class Queue {
  constructor(contents = []) {
    this._queue = [...contents];
  }
  pop() {
    const value = this._queue[0];
    this._queue.splice(0, 1);
    return value;
  }
}
```

### 2. 使用 extends 实现继承

更简单，且不会有破坏 `instanceof` 运算的危险：

```js
// ❌
const inherits = require('inherits');
function PeekableQueue(contents) {
  Queue.apply(this, contents);
}
inherits(PeekableQueue, Queue);
PeekableQueue.prototype.peek = function () {
  return this._queue[0];
}

// ✅
class PeekableQueue extends Queue {
  peek() {
    return this._queue[0];
  }
}
```

### 3. 补充

- 不写空的或仅转发 `super` 的无用构造器（Airbnb 9.5）
- 实例方法应使用 `this`，不依赖实例状态的方法声明为 `static`（Airbnb 9.7）

## 九、模块

### 1. 坚持使用 Module 标准写法

Module 语法是 JavaScript 模块的标准写法：使用 `import` 取代 `require`，使用 `export` 取代 `module.exports`：

```js
// ❌
const moduleA = require('moduleA');
const func1 = moduleA.func1;
const func2 = moduleA.func2;

// ✅
import { func1, func2 } from 'moduleA';
```

```js
// ❌ CommonJS 写法
const React = require('react');
class Breadcrumbs extends React.Component {
  render() {
    return <nav />;
  }
}
module.exports = Breadcrumbs;

// ✅ ES6 写法
import React from 'react';

export class Breadcrumbs extends React.Component {
  render() {
    return <nav />;
  }
}
```

### 2. 具名导出为主，default 导出仅限单导出文件

- 具名导出（named export）为主：命名全局一致，利于 tree-shaking 与 IDE 重命名、查找引用（Google 明确禁止 default export；TypeScript 官方 Do's and Don'ts 亦不建议 default）
- 仅一个导出的文件可使用 `export default`（Airbnb 10.6）
- 框架或工具有明确约定时跟随框架（如 Next.js 页面组件要求 default export）
- 无论采用哪种风格，同一项目内保持一致

```js
// ✅ 具名导出（优先）
export function makeStyleGuide() {
}
export const StyleGuide = {
  es6: {
  },
};

// 可接受：单导出文件用 default（函数名小写、对象名大写）
function makeStyleGuide() {
}
export default makeStyleGuide;
```

### 3. 不在模块输入中使用通配符

`import *` 会整体暴露命名空间、模糊依赖关系（三方指南共识）：

```js
// ❌
import * as myObject from './importModule';

// ✅
import myObject from './importModule';
import { func1 } from './importModule';
```

### 4. 导入导出细节

- 所有 `import` 置于文件顶部、非 import 语句之前（Airbnb 10.7）
- 同一路径只导入一次（Airbnb 10.4）
- 不导出可变绑定，仅导出常量引用（Airbnb 10.5）

```js
// ❌ 可变导出
let foo = 3;
export { foo };

// ✅
const foo = 3;
export { foo };
```
