# 二方库与依赖管理规范

> 本文件为 `../SKILL.md` 的补充规范：Maven 二方库发布与依赖管理的详细规则。核心条目见主文件“八、二方库与依赖管理”。

## 1. 二方库发布

- 版本号命名：`主版本号.次版本号.修订号`——主版本号：产品方向改变或大规模 API 不兼容；次版本号：相对兼容、增加主要功能；修订号：完全兼容、修 BUG 或新增次要功能；起始版本必须为 `1.0.0`
- 线上应用禁止依赖 `SNAPSHOT` 版本（安全包除外）；正式版本不允许覆盖升级
- 二方库接口返回值不允许使用枚举类型（或包含枚举的 POJO），参数可以使用
- 二方库不包含日志实现，只依赖日志门面（SLF4J）；不包含可执行配置项；移除不必要的 API 与依赖
- 每个版本的变化必须有记录，维护者与源码位置可查

## 2. 依赖管理

- 依赖一个二方库群时，定义统一版本变量（如 `${spring.version}`），避免同族库版本不一致
- 禁止同一 GroupId + ArtifactId 出现不同 Version（本地调试正常、线上冲突的先例很多）
- 版本仲裁统一放在 `<dependencyManagement>` 中；依赖声明放 `<dependencies>` 中
- 二方库新增或升级时，比对依赖仲裁结果（`dependency:resolve` / `dependency:tree`），保持除功能点外的其它 jar 仲裁不变，有变化必须明确评估
- 不依赖不稳定（无法保证向下兼容）的工具包
