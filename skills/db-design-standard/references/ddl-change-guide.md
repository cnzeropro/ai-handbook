# DDL 变更规范

> 本文件为 `../SKILL.md` 的补充规范：表结构变更（`ALTER TABLE`）的流程与安全要求。示例以 MySQL 呈现，其他数据库按"数据库适配说明"对应替换。

1. **变更前必须确认可回滚**：执行 DDL 变更前，确认存在备份或可回滚方案（全量备份、变更前导出的表结构/数据快照）；无回滚方案不得执行生产变更
2. **变更脚本必须评审**：所有 DDL 变更（加字段、改类型、加索引、删字段等）提交前走评审；多数据库项目各目标数据库的脚本同步交付
3. **大表变更使用在线方式**：大表（如超百万行；注意与分库分表阈值 500 万行区分——此处指在线变更的考虑起点）的加列、改索引必须使用在线变更，避免长时间锁表：
   - MySQL 8.0：即时加列（`ALGORITHM=INSTANT`）或 `ALGORITHM=INPLACE, LOCK=NONE`
   - 大规模重建类变更：使用 gh-ost / pt-osc 在线工具
4. **变更分批灰度**：预发布环境先行验证；生产变更避开业务高峰期，大批量数据订正分批执行
5. **新字段默认值安全**：新增字段默认值设为 `NULL` 或安全值，避免影响历史数据；加字段优先即时加列，禁止默认值计算类大表回填。与规则 3 的衔接：存量表先以 `NULL` 安全上线，数据回填校验后再收紧为 `NOT NULL` + 默认值
6. **删字段/改类型谨慎**：删除字段、修改字段类型属于高风险变更，须确认无依赖（应用、报表、上下游同步）后方可执行
7. **变更后验证**：变更后确认索引生效（`SHOW INDEX` / explain）、业务功能正常、慢查询无恶化
